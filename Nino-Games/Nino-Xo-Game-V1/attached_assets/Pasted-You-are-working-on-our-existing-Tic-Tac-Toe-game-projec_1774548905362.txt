FEATURE 1 — TOKEN SYSTEM
==================================================

Add a token system to the game.

Requirements:
- Each user should have a token balance stored in their account
- Each time a user wins a match, they should earn tokens
- Token rewards should be configurable if possible
- Tokens should be displayed clearly in the user profile / dashboard / wallet area
- Token transactions should be traceable if possible

Recommended implementation:
- Add a token_balance field to the user model
- Add a token_transactions table or equivalent history system
- Every token movement should be recorded with:
  - user_id
  - amount
  - type
  - source
  - description
  - related match id or challenge id if applicable
  - created_at

Suggested transaction types:
- match_win_reward
- challenge_entry_fee
- challenge_reward
- admin_adjustment
- refund

Recommendations:
- Prevent negative token balance unless explicitly allowed by admin
- Validate token updates carefully
- Make token handling server-side / backend-driven, not only frontend logic
- Keep token operations atomic to avoid bugs or exploits

FEATURE 2 — CHALLENGE SYSTEM
==================================================

Add a challenge system that can be created and managed by the admin from the admin panel.

Example:
The admin can create a challenge like:

- Total reward pool: 10,000 tokens
- Entry fee: 100 tokens

Reward distribution example:
- Rank 1: 5,000 tokens
- Rank 2: 3,000 tokens
- Rank 3: 2,000 tokens

Core requirements:
- Admin can create, edit, activate, deactivate, and complete challenges
- Each challenge must have:
  - title
  - description
  - cover image if possible
  - badge
  - entry fee in tokens
  - reward pool
  - reward distribution for top 3
  - start date
  - end date
  - status
  - max participants if needed
- Status options:
  - upcoming
  - active
  - completed
  - cancelled

Challenge participation:
- A user must pay the entry fee in tokens to join a challenge
- Only registered users for that challenge can play in that challenge
- Only registered users appear in that challenge ranking
- Challenge matches and rankings must be isolated from normal game mode

Leaderboard and ranking:
- Each challenge must have its own leaderboard
- Each challenge must have its own rank system
- Each challenge must have its own badge/visual identity
- Rankings should be based on a clear logic such as:
  - total wins
  - total score
  - total tokens earned inside challenge
  - win rate
  - or another solid ranking formula
- Choose the cleanest logic and implement it consistently

Reward distribution:
- When the challenge ends, the system should distribute rewards automatically to:
  - Rank 1
  - Rank 2
  - Rank 3
- Reward distribution must be safe and should not run multiple times accidentally
- Mark reward distribution status after execution

Recommendations:
- Add a participants table for challenge registrations
- Add challenge_match_history
- Add challenge_leaderboard data structure or compute rankings efficiently
- Add safeguard against duplicate registrations
- Add safeguard against joining without enough tokens
- Add refund logic only if admin cancels a challenge, if applicable
